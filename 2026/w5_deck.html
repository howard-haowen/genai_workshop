工作區 vs 部署區 ｜ Workspace vs Deploy

兩個區域分工：過程留在工作區，成品才進部署區

📂 專案工作區（完整研發過程）

  • 包含 raw/ 原始資料、私人筆記與草稿
  • 包含 wiki/、實驗腳本與 SKILL.md
  • ⚠️ 機密與未整理內容絕不直接對外發布

🌐 部署區（公開成果資料夾）

  • 只放經審核、確認可公開的展示成果
  • 必須有入口首頁 index.html 與公開資產
  • ✅ Actions 只會將此目錄打包並部署至全世界

GitHub Actions ｜ 運作機制

把「重複的手工步驟」寫成一張食譜，讓 GitHub 的雲端廚房代勞

📜 食譜：Workflow 檔案

一份寫在 Repo 裡的文字檔，記錄「遇到什麼情況，要依序做哪些事」。 

.github/workflows/
└── deploy.yaml

🔔 門鈴：觸發條件

食譜裡會寫明何時開工。例如你把檔案 push 到 main，就像按下門鈴，自動通知廚房開始作業。

👩‍🍳 廚房：雲端執行環境

GitHub 臨時借你一台雲端電腦，照食譜完成工作，做完就收掉，不占用你自己的電腦。

你不用每次親自下廚：食譜寫好一次，之後每次推送都會自動照做。

資安與隱私防線 ｜ Public vs Private

建立遠端 Repo 時，務必搞清楚 Public 與 Private 的差別

🌍 Public Repo（公開儲存庫）

  • 全世界任何人都能看到原始碼與 commit 紀錄
  • GitHub 免費帳號可直接支援 GitHub Pages
  • ⚠️ 嚴禁包含 API Key、密碼、個人隱私資料

🔒 Private Repo（私人儲存庫）

  • 僅有你與被邀請的協作者能存取
  • 適合未公開研究、個人知識庫與原始機敏筆記
  • 💡 免費版 Private Repo 預設無法使用 Pages（付費/學生方案除外）

部署流程總覽 ｜ GitHub Pages

五個步驟，把成果部署到 GitHub Pages

1️⃣ 註冊 GitHub 帳號

到 github.com 免費註冊，記下你的 <username>（申請教學 ↗）。

2️⃣ 本機認證 GitHub

執行 gh auth login，再用 gh auth status 確認登入。

3️⃣ 新增 Repo

gh repo create <repo-name> --public --source=. --remote=origin

4️⃣ 決定部署內容

只放要公開的成果（含 index.html），用 .gitignore 排除 raw/ 與私人筆記；Agent 產生 deploy.yaml 後 git push。

5️⃣ 取得 Pages 網址

到 Settings → Pages 將 Source 設為 GitHub Actions；部署完成後網址為
https://<username>.github.io/<repo>/

人類決定「放什麼、叫什麼」，其餘指令都可以交給 Agent 透過 git / gh CLI 完成。

參考閱讀：GitHub Pages →

動態網頁部署 ｜ Vercel

部署到 Vercel：先預覽、再上線，由 Agent 自動判斷流程

1️⃣ 診斷專案

Agent 檢查專案是否已連結 Vercel、是否有 Git 遠端。

2️⃣ 選擇路徑

  • 有 Git 遠端 Repo：push 後由 Vercel 自動建置
  • 沒有 Git 遠端 Repo：用 vercel deploy 直接上傳

3️⃣ 預覽部署

預設先建立 Preview，確認無誤才推到 Production。

4️⃣ 取得網址

Agent 回報 Preview 或正式網址，不必進控制台找連結。

還沒登入 Vercel？Agent 可先建立免登入的臨時部署，之後再認領到自己的帳號。

你只要說：「幫我把這個專案部署到 Vercel，給我預覽連結」，其餘交給 deploy-to-vercel Skill。

參考閱讀：Vercel Docs →
