AI Agent 定義

不是只會聊天，而是能完成任務的 AI 工作夥伴

AI Agent = LLM 🧠 + 目標 🎯 + 脈絡 📚 + 工具 🛠️ + 檢查 ✅

LLM 是理解與生成的核心；Agent 會用它理解目標、讀取脈絡、使用工具，執行後再檢查結果；像一位會照工作手冊做事、也會回報進度的數位助理。

🧠 LLM

負責理解文字、生成內容，提供推理與語言能力。

🎯 目標

先知道要完成哪一件事，而不只是回答一句話。

📚 脈絡

讀懂專案規則、檔案內容與使用者偏好。

🛠️ 工具

能讀寫檔案、呼叫 API、執行 CLI 或使用外部服務。

✅ 檢查

完成後回頭確認結果是否符合規則與任務需求。

AGENTS.md：像寫給研究助理的工作手冊

📋 課堂規則

就像老師先告訴助教：作業格式、評分標準、不能亂改的地方。

🧭 研究方向

告訴 Agent 這個專案在做什麼、資料在哪裡、要用哪種語氣與語言。

📍 放在現場

規則可放在專案根目錄；子資料夾也能放更細的在地規則。

一句話：先把「怎麼做才算對」寫清楚，Agent 才不會每次都猜。

SKILL.md：像一張可重複使用的任務食譜

🍳 食譜

不用每次重新教，直接寫下材料、步驟、注意事項與完成標準。

🔁 重複任務

適合整理文獻、製作簡報、轉換格式、產生固定樣式文件。

一句話：把你常做的事變成「下次也能照做」的方法。

關鍵詞 3

MCP（Model Context Protocol）：像萬用轉接頭

🔌 轉接頭

不同工具原本插孔不同，MCP 把它們接成 Agent 聽得懂的形式。

☎️ 接線員

Agent 不必懂每個服務的細節，只要透過標準介面提出需求。

📚 圖書館櫃台

它幫 Agent 查資料、拿資源、操作外部服務，再把結果帶回來。

一句話：MCP 讓 Agent 可以安全、標準化地連到外部工具與資料。

關鍵詞 4

A2A（Agent to Agent）：像跨組別的任務交接

🤝 分組合作

一個 Agent 不必什麼都會，可以把工作交給更適合的 Agent。

🪪 名片

Agent card 像名片，說明自己會做什麼、怎麼被呼叫。

📝 交接單

委派任務時，把需求、輸入、成果格式交代清楚，避免雞同鴨講。

一句話：A2A 讓不同專長的 Agent 能彼此委派與協作。

14 / 32
關鍵詞 5

Subagents：像專題報告裡的小組分工

🔎 搜尋組

資料太多時，派子 Agent 先找資料、比對來源、整理候選內容。

🧹 整理組

子 Agent 可負責摘要、分類、檢查格式，主 Agent 保留大方向。

📣 回報組

完成後只回報重點與證據，讓主 Agent 整合成最後成果。

一句話：把大任務拆小，讓主 Agent 不被細節塞爆。

AGENTS.md 內容解析

一份實用的 AGENTS.md 至少要回答三件事

專案概述

這是什麼專案、目標是什麼、重要資料在哪裡。

規則與限制

語言、資料來源、隱私邊界、不可編造的內容與操作限制。

檢查方式

完成後要跑什麼驗證、怎麼確認產出是否合格。 

# AGENTS.md

## 專案概述
這是一個個人 LLM Wiki 專案，用來整理閱讀筆記與研究素材。

## 規則與限制
- 輸出語言：繁體中文
- 不可編造引用內容
- 原始素材放在 raw/，不可直接公開

## 檢查方式
- 確認 wiki/index.md 與 wiki/overview.md 已更新
- 需要公開的內容才輸出到 artifacts/webpages/
- 不確定之處標記「需確認」

使用流程

與 IBM Bob 互動的四個步驟

從登入到 Agent 執行，整個流程只需幾分鐘

STEP 01 🌐

登入 Bob

  • 開啟 IBM Bob
  • 使用 SSO 登入
  • 進入 Bob 工作區
STEP 02 📁

開啟專案資料夾

  • 在 Bob 中開啟或建立專案程式碼資料夾
  • Bob 自動掃描並理解程式碼
STEP 03 📋 Plan Mode

規劃 Plan

  • 輸入任務需求描述
  • Bob 在 Plan Mode 下自動拆解步驟、生成執行計畫
  • 使用者確認後才進入下一步
STEP 04 🤖 Agent Mode

執行 Agent

  • 確認計畫後切換 Agent Mode
  • Bob 自動執行所有步驟，檔案修改、測試、提交一氣呵成
  • 全程可隨時暫停或介入
