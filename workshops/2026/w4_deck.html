MCP 是什麼

統一 AI Agent 與工具／資料來源的連接方式

MCP = 統一介面 🔌 + 外部工具 🛠️ + 資料來源 📚 + 權限邊界 🚧

MCP 不是某一個工具，而是一種協定：把某個工具或資料來源包成標準介面，讓懂 MCP 的 Agent 都能用同一種方式使用它。

🔌 轉接頭

不同工具原本插孔不同，MCP server 把它們接成 Agent 聽得懂的形式。

☎️ 接線員

Agent 不必懂每個服務的細節，只要透過標準介面提出需求。

🚪 有門禁的房間

每個 MCP server 只開放特定範圍的資料，不是任意進出。

MCP 的資料流

一個請求，怎麼變成外部世界的一個動作

🗣️ 使用者請求

你告訴 Agent 想做什麼，例如「幫我整理 Zotero 裡的文獻」。

🔌 MCP Server

把請求轉成該工具聽得懂的操作，並檢查是否在允許範圍內。

🌐 外部工具／資料

實際查詢 Zotero 文獻庫、存取 Google Workspace 等外部服務或資料來源。

📩 回應 Agent

結果被整理、格式化，回傳給 Agent 繼續完成任務。 

使用者請求 → MCP Server（權限檢查） → 外部工具／資料 → 回應 Agent

Skills vs MCP
09 / 23
銜接閱讀

Skill 與 MCP 常搭配使用，但 MCP 是最後手段

  • SKILL.md（W3）定義 Agent「怎麼做」，是可攜式、可重用的工作指令。
  • MCP（W4）打開 Agent「能碰到什麼」，讓 Agent 真正存取外部服務與資料。
  • 兩者常搭配：Skill 決定怎麼做，MCP 決定能碰到哪裡。
  • ⚠️ MCP 是 last resort：能用 Skill 或 CLI 解決的，就不需要 MCP。只在真的必須即時存取外部服務時才引入。

16,815 vs 98：兩種接法的上下文成本
