工具的三個層次

Agent 的工具：從內建到客製

🧰 內建工具

Agent 平台預裝的工具，開箱即用。例如 IBM Bob 內建 read_file、execute_command、grep、apply_diff 等數十種工具，涵蓋檔案讀寫、程式碼搜尋與系統操作。

🎓 Skills

透過 SKILL.md 賦予 Agent 特定領域的知識與工作方式。Skills 是可攜式的指令集，讓 Agent 學習你的個人工作流程，跨平台都能沿用。

🔌 MCP Servers

透過 Model Context Protocol 接入外部服務。每一個 MCP Server 就像為 Agent 安裝一套新應用，讓它能操作 Obsidian、瀏覽網頁、讀取 RSS 等真實世界的工具。

工具不夠用？先問自己：該用內建工具、補一個 Skill，還是接一個 MCP Server？

關鍵詞 3、4、5

三種介面，一個比喻就記住

⌨️ CLI
Command-Line Interface

就像寫信給圖書館員：你用文字說清楚「請幫我找 1984 年後出版、作者是卡夫卡的德文原著」，館員照著指令精確執行。

✅ 精確、可重複、留有紀錄
Agent 最愛用的語言

🖥️ GUI
Graphical User Interface

就像進書店：你靠封面、陳列方式與書店地圖找書，眼睛一掃就能判斷、比較與挑選。

✅ 視覺直觀、易於判斷脈絡
人類最舒適的操作方式

🤖 ACI
Agentic Computer Interface

就像對著助理說「幫我訂明天早上九點的會議室」——你不需要告訴他每一個步驟，他自己打開系統、找到表單、填完送出。

✅ 只需描述目標，不需給步驟
⚠️ 2025 年起快速成熟中

title、author_name、first_publish_year 在哪裡？

Step 2 ── 讓 Bob 接手

讀取 https://openlibrary.org/developers/api API 文件，然後幫我查詢 Taiwan Travelogue，列出書名、作者與首次出版年份。

這個 API 能做什麼
  • 批次檢索：單一請求回傳多本書目完整資料。
  • 雙層架構：Work 層（作者、首版年）與 Edition 層（書名、封面）。
  • 靈活過濾：可附帶出版年、版本數等篩選條件。

API vs CLI

兩種工具，一個共同目標：讓 Agent 精準執行

🌐 API

是什麼

透過 HTTP 請求，向遠端服務要資料或觸發動作。Agent 不需要安裝任何東西，直接送出請求就有回應。

對 Agent 的價值

取得即時數據（書目、天氣、匯率）、觸發外部服務（傳訊、寫日曆）——連接網路世界的橋樑。

限制

必須有網路、依賴第三方服務的規格，無法直接操作本機檔案。

⌨️ CLI

是什麼

在終端機輸入指令，直接控制本機系統——建立檔案、執行程式、處理媒體，完全離線也能運作。

對 Agent 的價值

讀寫檔案、安裝套件、執行腳本——掌控本機環境的雙手，讓 Agent 真正能「做事」而非只會「查資料」。

限制

需要安裝對應工具，指令語法因平台（Windows / macOS）略有差異。

🤖

AI Agent 同時擁有兩種能力：用 API 連接世界、用 CLI 控制本機——這就是為什麼它比人類更有效率地完成跨系統任務。
